ووصف من سطر واحد، والأسماء الأخرى التي تُعرف بها. هذه هي القطعة التي لا يرغب أحد في تصميمها
من الصفر عند بناء دليل أدوات، وينتهي الجميع إلى تصميمها تصميمًا سيئًا.

المستوى الأعلى هنا هو نفسه التصنيفات العشرون المستعملة في مجموعة بيانات أدوات الذكاء
الاصطناعي من TiorAI، وهذا مقصود: يمكنك تبنّي المستوى الأعلى وحده فتبقى متوافقًا مع بيانات
منشورة، أو تبنّي المستويين معًا فتحصل على التفصيل. أما ابتكار مستوى أعلى ثانٍ فكان سيجعل
مستودعين من TiorAI يختلفان علنًا على الشيء نفسه.

بإشراف [TiorAI](https://tiorai.com/)، وعملها اليومي فهرسة أدوات الذكاء الاصطناعي.

## الكتابة والمحتوى

صياغة المواد المكتوبة وتحريرها وإنتاجها.

- **إعادة الصياغة** — إعادة قول نص قائم بطول أو مستوى لغوي مختلف. `paraphrasing-and-rewriting`
- **التدقيق اللغوي والأسلوبي** — تصحيح القواعد وفرض أسلوب موحّد عبر النص. `grammar-and-style-checking`
- **الترجمة والتوطين** — نقل النص بين اللغات وتكييفه لجمهور محلي. `translation-and-localisation`
- **التلخيص** — اختصار المستندات والتفريغات والنقاشات إلى جوهرها. `summarisation`
- **الكتابة الأكاديمية والتقنية** — أوراق بحثية وتوثيق وكتابة تتطلب دقة أو إسنادًا للمصادر. `academic-and-technical-writing`
- **الكتابة الطويلة** — صياغة المقالات والتقارير والكتب وسائر القطع الممتدة. `long-form-writing`
- **كتابة السيناريو** — الكتابة للفيديو والبودكاست والإلقاء المنطوق. `scriptwriting`
- **كتابة النصوص الإعلانية** — نصوص إقناعية قصيرة للإعلانات وصفحات الهبوط وصفحات المنتج والبريد. `copywriting`
- **كشف المحتوى المولّد** — تقدير ما إذا كان النص مكتوبًا بواسطة آلة. `ai-content-detection`

## توليد الصور وتحريرها

إنشاء الصور الثابتة وتعديلها.

- **إزالة الخلفية** — فصل الموضوع عن خلفيته في الصورة. `background-removal`
- **الشعارات وأصول الهوية** — العلامات والأيقونات والأصول المتجهية للهوية البصرية. `logo-and-brand-assets`
- **الصور الشخصية والأفاتار** — توليد صور شخصية لشخص انطلاقًا من صور مُقدَّمة. `headshots-and-avatars`
- **تحرير الصور** — تعديل صورة قائمة، بما يشمل الملء الذكي وإزالة العناصر. `image-editing`
- **تصوير المنتجات** — إنتاج صور الكتالوج والمتاجر الإلكترونية أو تحسينها. `product-photography`
- **رفع الدقة والترميم** — رفع دقة الصور وإصلاح التالف ومنخفض الجودة منها. `upscaling-and-restoration`
- **من نص إلى صورة** — توليد صورة انطلاقًا من وصف مكتوب. `text-to-image`
- **واجهات برمجة الصور** — وصول برمجي إلى نماذج التوليد والتحرير. `image-apis`

## الفيديو

إنتاج الصور المتحركة وتحريرها وإعادة توظيفها.

- **التحريك والموشن جرافيك** — تحريك الصور الثابتة والشخصيات والرسوم المتحركة. `animation-and-motion`
- **التقطيع وإعادة التوظيف** — تقطيع اللقطات الطويلة إلى مقاطع رأسية قصيرة. `clipping-and-repurposing`
- **الدبلجة والترجمة المرئية** — ترجمة الصوت المنطوق ومطابقته مع الصورة. `dubbing-and-subtitling`
- **المقدّمون الافتراضيون** — مقدّمون مركّبون أمام الكاميرا يؤدّون نصًا مكتوبًا. `ai-avatars-and-presenters`
- **تحرير الفيديو** — قص اللقطات القائمة وتركيبها وتصحيح ألوانها. `video-editing`
- **تحسين الفيديو** — رفع الدقة وتثبيت الصورة وإزالة التشويش وزيادة معدل الإطارات. `video-enhancement`
- **من نص إلى فيديو** — توليد لقطات مصوّرة انطلاقًا من وصف مكتوب. `text-to-video`
- **واجهات برمجة الفيديو** — وصول برمجي إلى توليد الفيديو ومعالجته. `video-apis`

## الصوت والموسيقى والتعليق الصوتي

الكلام والصوت والموسيقى، وكل ما يُسمع لا يُقرأ.

- **إنتاج البودكاست** — تسجيل البرامج الحوارية وتحريرها ونشرها. `podcast-production`
- **استنساخ الصوت** — إعادة إنتاج صوت بعينه انطلاقًا من عيّنة منه. `voice-cloning`
- **الوكلاء الصوتيون** — أنظمة تُجري محادثة منطوقة وتنفّذ إجراءات بناءً عليها. `voice-agents`
- **تحرير الصوت ومعالجته النهائية** — تركيب الصوت وموازنته وإخراجه في صورته النهائية. `audio-editing-and-mastering`
- **تحسين الصوت** — إزالة الضوضاء والصدى والتشوّهات من التسجيلات. `audio-enhancement`
- **توليد الموسيقى** — تأليف الموسيقى والخلفيات الصوتية أو إنتاجها. `music-generation`
- **من كلام إلى نص** — تحويل الصوت المنطوق إلى نص مكتوب. `speech-to-text`
- **من نص إلى كلام** — تحويل النص المكتوب إلى صوت منطوق. `text-to-speech`
- **واجهات برمجة الكلام** — وصول برمجي إلى التعرف على الكلام وتوليده. `speech-apis`

## البرمجة والتطوير

كتابة البرمجيات ومراجعتها واختبارها وإطلاقها.

- **DevOps والبنية التحتية** — التكامل والنشر المستمر، والبنية ككود، والحوادث والتشغيل. `devops-and-infrastructure`
- **أمن التطبيقات** — العثور على الثغرات في الكود والاعتماديات وإصلاحها. `application-security`
- **إكمال الكود** — اقتراح الأسطر التالية أثناء كتابة المطوّر. `code-completion`
- **الاختبار وضمان الجودة** — توليد الاختبارات وصيانتها وتشغيلها. `testing-and-qa`
- **التوثيق** — توليد توثيق المطوّرين وصيانته مع تغيّر الكود. `documentation`
- **تصحيح الأخطاء** — تحديد العيوب في البرمجيات العاملة وشرح أسبابها. `debugging`
- **توليد الواجهات** — إنتاج كود الواجهة انطلاقًا من تصميم أو وصف. `frontend-and-ui-generation`
- **قواعد البيانات وSQL** — كتابة الاستعلامات وتصميم المخطّطات وشرح خطط التنفيذ. `database-and-sql`
- **محرّرات الأكواد الذكية** — محرّرات وبيئات تطوير مبنية حول نموذج لغوي. `ai-code-editors`
- **مراجعة الكود** — مراجعة آلية للتغييرات قبل دمجها في المشروع. `code-review`
- **مساعدات سطر الأوامر** — أدوات مدعومة بنموذج تُدار من سطر الأوامر. `terminal-assistants`
- **وكلاء البرمجة** — أنظمة تنفّذ مهمة برمجية ممتدة عبر عدة ملفات. `coding-agents`

## بنية المطوّرين والنماذج

ما يُبنى عليه أي تطبيق ذكاء اصطناعي.

- **أطر RAG** — مكتبات لمسارات التوليد المعزّز بالاسترجاع. `rag-frameworks`
- **أطر بناء الوكلاء** — مكتبات لبناء أنظمة تخطّط وتستعمل الأدوات. `agent-frameworks`
- **إدارة التوجيهات** — إصدار التوجيهات واختبارها ونشرها بوصفها أصولًا مستقلة. `prompt-management`
- **استضافة النماذج وتشغيلها** — تشغيل النماذج على بنية مُدارة أو مملوكة ذاتيًا. `model-hosting-and-serving`
- **البيانات التركيبية** — توليد بيانات للتدريب والتقييم. `synthetic-data`
- **الضوابط والإشراف** — تقييد ما يدخل إلى النموذج وما يخرج منه. `guardrails-and-moderation`
- **المراقبة والتتبّع** — تسجيل التوجيهات واستدعاءات الأدوات والتكلفة والزمن لكل طلب. `observability-and-tracing`
- **بوّابات النماذج** — نقطة وصول واحدة أمام عدة مزوّدين للنماذج. `llm-gateways`
- **قواعد البيانات المتجهية** — تخزين التضمينات والبحث عن أقرب جار فيها. `vector-databases`
- **منصّات التقييم** — قياس جودة المخرجات مقابل مجموعات بيانات ومعايير محدّدة. `evaluation-platforms`
- **منصّات الضبط الدقيق** — تكييف نموذج أساس على مهمة أو أسلوب بعينه. `fine-tuning-platforms`
- **واجهات برمجة النماذج** — وصول مُستضاف إلى نماذج اللغة والصورة والكلام والتضمين. `model-apis`

## المساعدات ومحركات المحادثة

أنظمة المحادثة العامة، والواجهات التي يلتقي الناس بالنموذج من خلالها.

- **الشخصيات وتقمّص الأدوار** — محادثة قائمة على شخصية، وأدب تفاعلي. `character-and-roleplay`
- **المساعدات العامة** — منتجات محادثة واسعة الاستعمال في الحياة اليومية. `general-assistants`
- **المساعدات المحلية والخاصة** — مساعدات تعمل على عتاد المستخدم نفسه. `local-and-private-assistants`
- **بناء المساعدات المخصّصة** — أدوات بلا كود لبناء مساعد يحمل هوية العلامة. `custom-assistant-builders`
- **محرّكات الإجابة** — بحث يعيد إجابة مكتوبة مع مصادرها. `answer-engines`
- **مساعدات المتصفح** — مساعدات تعمل داخل متصفح الويب نفسه. `browser-assistants`
- **منصّات متعددة النماذج** — واجهات تعرض نماذج عدة مزوّدين جنبًا إلى جنب. `multi-model-platforms`

## الأتمتة والوكلاء

عمل يجري دون أن يقود شخصٌ كل خطوة فيه.

- **أتمتة إدخال البيانات** — استخراج بيانات منظّمة من المستندات ونقلها إلى الأنظمة. `document-and-data-entry-automation`
- **أتمتة البريد** — فرز عمل صندوق الوارد وصياغته وتوجيهه. `email-automation`
- **أتمتة العمليات الروبوتية** — أتمتة العمل عبر تطبيقات سطح المكتب وتطبيقات المؤسسات. `robotic-process-automation`
- **أتمتة المتصفح والويب** — قيادة متصفح لجمع البيانات أو إتمام المهام. `browser-and-web-automation`
- **أتمتة سير العمل** — ربط التطبيقات ليُطلق حدثٌ واحد سلسلةً من الإجراءات. `workflow-automation`
- **بناء الأدوات الداخلية** — بناء واجهات داخلية فوق بيانات قائمة. `internal-tools-and-app-builders`
- **وكلاء المهام والبحث** — وكلاء يلاحقون هدفًا عبر عدة أدوات. `task-and-research-agents`

## الإنتاجية وسير العمل

إنجاز العمل الفردي والجماعي: الملاحظات والاجتماعات والبريد والمهام والوقت.

- **إدارة المعرفة** — ربط الملاحظات والمستندات والمراجع في شيء قابل للبحث. `knowledge-management`
- **إدارة المهام والمشاريع** — تخطيط العمل وتوزيعه ومتابعة إنجازه. `task-and-project-management`
- **الأتمتة الشخصية** — أتمتة صغيرة لروتين الفرد نفسه. `personal-automation`
- **البحث في أدوات العمل** — البحث عبر التطبيقات التي تستعملها المؤسسة. `workplace-search`
- **التقويم وجدولة المواعيد** — ترتيب الوقت وتنسيق المواعيد المشتركة. `calendar-and-scheduling`

## بنية البيانات

سجل واحد لكل تصنيف، في أي من المستويين. النسخة التي تصلح للتحقق الآلي هي
[`data/schema.json`](data/schema.json).

| الحقل | النوع | ملاحظات |
|---|---|---|
| `name` | نص | الاسم المعروض |
| `slug` | نص | معرّف ثابت، فريد عبر المستويين. مشتق من الاسم، لكنه لا يتغيّر حين يتغيّر الاسم |
| `parent` | نص أو `null` | معرّف الأب في المستوى الأول، و`null` في المستوى الأول نفسه |
| `level` | عدد | `1` أو `2`. ولا يوجد مستوى ثالث، عن قصد |
| `description` | نص | جملة واحدة، من ٥ إلى ٢٢ كلمة |
| `aliases` | مصفوفة نصوص | أسماء أخرى للتصنيف نفسه، ومنها الاختصارات والرسم الأمريكي |
| `children` | مصفوفة نصوص | معرّفات الفروع. فارغة في المستوى الثاني |
| `last_reviewed` | نص | تاريخ بصيغة `YYYY-MM-DD` |

تُفحص الشجرة قبل الإصدار: كل `parent` وكل عنصر في `children` يشير إلى عقدة موجودة، ولا يتكرر
اسم في أي موضع من الشجرة، ولا تحمل عقدة في المستوى الثاني فروعًا خاصة بها.

## كيف نختار التصنيفات

يستحق التصنيف موضعه حين يجيب عن سؤال يصل به الناس فعلًا. «توليد الصور من نص» تصنيف لأن
الناس يبحثون عنه بهذه العبارة، أما «التخليق البصري التوليدي» فليس تصنيفًا لأن أحدًا لا يبحث
عنه.

القواعد التي بُنيت عليها الشجرة:

- **مستويان، لا ثلاثة.** المستوى الثالث هو حيث تموت التصنيفات: يُنتج عقدًا فيها عنصر واحد،
  ويفرض حكمًا اجتهاديًا عند كل أداة جديدة.
- **من ستة إلى اثني عشر فرعًا لكل تصنيف رئيسي.** دون الستة لا يحمل المستوى وزنه وتعود فروعه
  إلى ما فوقها، وفوق الاثني عشر يكون التصنيف في الحقيقة تصنيفين.
- **التسمية بالمهمة لا بالتقنية.** «مساعدو الاجتماعات» لا «تفريغ وتلخيص متعدد الوسائط».
- **المرادفات تحمل الصيغ المختلفة.** `personalization` و`tts` و`cro` و`localization` مرادفات
  لا عقد مستقلة، فينجح البحث أيًا كانت الصيغة التي كتبها المستخدم.
- **لا عقدة باسم منتج بعينه.** التصنيف المسمّى باسم منتج هو صفحة منتج.

وما استُبعد عمدًا: مستوى ثالث، وتصنيفات لا وجود لها خارج عبارة تسويقية، والقطاعات الرأسية
(فتصنيف الأدوات ليس تصنيفًا للعملاء)، وأي عقدة لا يمكن أن تضم عددًا معقولًا من المنتجات
المتمايزة.

## استخدام البيانات

ابنِ الشجرة:

```python
import json

nodes = json.load(open("data/categories.json"))
by_slug = {n["slug"]: n for n in nodes}
for top in (n for n in nodes if n["level"] == 1):
    print(top["name"])
    for c in top["children"]:
        print("   ", by_slug[c]["name"])
```

حلّ ما كتبه المستخدم أيًا كانت صيغته، مع المرادفات:

```python
def resolve(q, nodes):
    q = q.strip().lower()
    for n in nodes:
        if n["slug"] == q or n["name"].lower() == q:
            return n
        if q in [a.lower() for a in n["aliases"]]:
            return n
    return None
```

ارفع معرّفًا من المستوى الثاني إلى تصنيفه الرئيسي:

```python
def top_level(slug, by_slug):
    n = by_slug[slug]
    return by_slug[n["parent"]] if n["parent"] else n
```

تحقّق من صحة الملف قبل أن تبني عليه:

```bash
pip install check-jsonschema
check-jsonschema --schemafile data/schema.json data/categories.json
```

المعرّفات هي العقد. الأسماء تُحرَّر لأجل الوضوح، أما المعرّفات فلا تتغيّر، فيبقى كل ما بنيته
عليها عاملًا عبر الإصدارات.

## حدود معروفة

- **التصنيف رأي.** هذا الرأي تشكّل مما يبحث عنه الناس ومما يحتاج دليل أدوات إلى ترتيبه. وثمة
  شجرة أخرى معقولة تضع استخراج البيانات من المستندات تحت الأتمتة بدل المستندات، ولن تكون
  مخطئة.
- **بعض الأدوات تنتمي إلى أكثر من موضع.** الشجرة لا تحل هذه المسألة، بل تعطيك عقدًا ثابتة
  ترتّب عليها، ويبقى قرار السماح بأكثر من انتماء قرارك أنت.
- **لا تصنيفات قطاعية.** الصحة والقانون والتعليم ترد بوصفها عملًا لا بوصفها قطاعات. والأداة
  التي تُباع للمستشفيات تبقى أداة تفريغ صوتي.
- **مستويان يعنيان أن بعض العقد واسعة.** «أتمتة سير العمل» تغطي الكثير. وهذا ثمن رفض المستوى
  الثالث، وهو ثمن يستحق الدفع.
